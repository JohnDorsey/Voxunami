Mutation experiments on the deterministic memory limit (2026-11-16, Windows)
==========================================================================
Each mutant breaks one rule in a backed-up copy of the source, runs the tests that should notice, and restores the
file (harness: scratch script, not kept). KILLED = at least one test failed.

Not a clean single run: the log below is the first full run (M1-M12), then a rerun of M4 and M10.
- M10 first ran with a pattern that rustfmt had reflowed ("HARNESS ERROR"); the rerun at the end is the real result.
- M4's integration test survived both times. Reason, read from the code and confirmed by the result: every bulk
  allocation charges steps in proportion to its size (a step per 16 bytes at the least), which already carries a walk
  past its spacing, so the "measure a bulk allocation at once" rule is a second guard that no script can currently get
  past. Only the unit test in monty-types pins it. I kept the rule and say so in the test comment.
- M9 (a new heap object is not reported to the tracker) is killed by four tests, one of them the bulk test added after
  the first run, so that hook is not dead code.
